# The Malfatti circles in Lean 4

A Lean 4 + Mathlib formalisation of the **existence of the Malfatti circles** of a triangle,
together with **Malfatti's radius formula**.

> In every nondegenerate triangle in the Euclidean plane there are three circles of positive radius
> such that circle `i` is tangent to the two side lines through vertex `i`, with its centre strictly
> on the interior side of each, and any two of the circles are externally tangent. Their radii are
> `ρ_i = r / (2(s − a_i)) · (s − r − (IA_{i+1} + IA_{i+2} − IA_i))`.

Here `r` is the inradius, `I` the incentre, `s` the semiperimeter and `a_i` the side opposite
vertex `i`. The statements use Mathlib's `Affine.Triangle`, `incenter`, `inradius`, `touchpoint`,
`Sphere.IsTangent` / `IsTangentAt`, `Sphere.IsExtTangent` and `AffineSubspace.SSameSide`.

The circles are constructed explicitly: centre `O_i = A_i + μ_i (I − A_i)` on the bisector, radius
`μ_i r`, with `μ_A = (1+q)(1+w) / (2(1+p))`, where `p, q, w` play the role of `tan(A/4)`,
`tan(B/4)`, `tan(C/4)`. Side tangency follows by homothety from the incircle. Heron's relation
`r²s = (s−a)(s−b)(s−c)` (`heron`) is proved from the barycentric description of the incentre and a
Gram-matrix identity with an explicit `linear_combination` certificate; it gives `K(p, q, w) = 0`,
the tangent form of `A/4 + B/4 + C/4 = π/4` (`K_eq_zero_of_heron`). Pairwise tangency and the radius
formula are polynomial identities that are multiples of `K` (`dist_identity`, `radius_eq`).

**Status:** all statements proved, with no `sorry`. `gate.sh` checks 77 named declarations.

## Main statements

All in namespace `Malfatti`. The headline theorems are over `EuclideanSpace ℝ (Fin 2)`; the
general versions are over any `t : Affine.Triangle ℝ P` with `[Fact (finrank ℝ V = 2)]`.

## Verification

`./gate.sh` builds the library and generates its own `#print axioms` queries for 77 named
declarations, fully qualified (every declaration cited in `SPIKE_REPORT.md`, plus the supporting
lemmas, definitions, bridges and witnesses). The queries are generated by the gate itself, not read
from a file in the repository.

The gate fails if any of the following is true:
- a source file (`Malfatti/*.lean`, `Malfatti.lean`) contains `sorry`, `admit`, `native_decide`, `axiom`, `#eval`, `run_cmd`, `initialize`, `IO`, `set_option`, `macro`/`elab`/`syntax`/`notation`/`infix`/`prefix`/`postfix`, `import Lean` or `open Lean`;
- the build fails;
- a named declaration is missing, or has an extra report;
- a named declaration depends on anything other than `propext`, `Classical.choice` and `Quot.sound`.

Output: `PASS (77 declarations, standard axioms only)`. Some of these are definitions, which may
use a subset of the three axioms.

`tests/tamper.sh` plants six kinds of fake proof in scratch copies (in `Malfatti/Main.lean`, and for
`falsehyp` in `Malfatti/Algebra.lean`) and checks that the gate rejects each one (a rejection must
exit nonzero and print the expected `FAIL` message). The real repository is never modified.

| Test | What it plants |
|---|---|
| sorry | a `sorry` |
| ax2line | an axiom split across two lines |
| evalfake | an `#eval` that prints a fake axiom report |
| macro | a custom macro that rewrites `#print axioms` |
| falsehyp | the hypothesis `K p q w = 0` dropped from `mu_lt_one` (false: `p = 1/10`, `q = w = 9/10` gives `mu = 361/220 > 1`) |
| wrap | a genuine extra axiom with a long name, so the report wraps over several lines |

`tests/tamper.sh` needs a prior `lake build` (it reuses `.lake/build`); run the tests one at a time.
Both scripts use only POSIX shell tools and `awk` (no GNU `sed -i`, no GNU `mktemp` extensions,
no Python).

`code/check_malfatti.py` checks the mathematics independently in floating point (output in
`code/check.out`): over 2 000 random triangles the formula radii, with centres on the bisectors,
have maximum tangency error (to the sides and pairwise) about `2.6e-10`; adding `0.01` inside the
bracket of the formula gives errors of at least `6.5e-3`; and for the equilateral triangle the
three Malfatti circles have total area `0.315670`, less than the `0.319977` of the incircle plus
two corner circles (the Lob–Richmond observation). `SPIKE_REPORT.md` is the development log; it
mentions certificate-generation scripts, a scratch axiom file and build logs that are not part of
this repository.

## Scope

- Only **existence** is proved, by verifying an explicit construction; uniqueness of the Malfatti
  circles is not proved.
- Containment is proved only in part: the tangency points lie on the side segments and the centres
  lie in the interior half-planes, but it is not proved that each circle lies inside the triangle.
- Malfatti's area *problem* (the circles are never optimal; Lob–Richmond, Zalgaller–Los') is not
  formalised; the counterexample is checked numerically only.

## Prior art

A best-effort search (the Mathlib `v4.33.1` sources including `Archive/`, `docs/100.yaml` and
`docs/1000.yaml`; the Isabelle AFP; HOL Light; HOL4; GeoCoq; the Rocq 100-theorems collection; the
Mizar Mathematical Library; GitHub code and repository search for Lean, Coq, Isabelle, SML and OCaml)
found no formalisation of the Malfatti circles. The only related item is an open wishlist entry in a
Mathlib issue (#6091) for the different statement that the Malfatti circles are never optimal. No
claim of priority beyond this search is made.

## Build

```sh
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh   # if Lean is not installed
lake exe cache get
lake build
./gate.sh
bash tests/tamper.sh
```

Requirements: a working `git` (Lake uses it to fetch the pinned Mathlib) and the pinned Lean
toolchain, Lean `v4.33.1` (`lean-toolchain`; `elan` installs it automatically), with Mathlib
`v4.33.1` (revision pinned in `lake-manifest.json`). `gate.sh` never fetches: run
`lake exe cache get` (or `lake build`) first so that the pinned Mathlib checkout is present in
`.lake/packages`.

## How to run the checks

From the repository root, after the build steps above:

```sh
lake build                 # build the library (pinned Lean and Mathlib)
./gate.sh                  # sorry/axiom/token gate; prints PASS (N declarations, standard axioms only)
bash tests/tamper.sh       # plants six fake proofs in scratch copies; each must be rejected
python3 code/check_malfatti.py   # independent floating-point check (not part of the proof)
```

`gate.sh` exits nonzero on any failure. `tests/tamper.sh` reuses `.lake/build`, so run `lake build`
first. The checker script is deterministic (fixed random seed) and needs only Python 3 and its standard library. Its output is stored in `code/check.out`; to compare, run `python3 code/check_malfatti.py | diff - code/check.out`.
